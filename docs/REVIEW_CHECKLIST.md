# Review-Checkliste

## Fachlichkeit
- [ ] Umsetzung entspricht dem freigegebenen Use Case.
- [ ] Akzeptanzkriterien sind vollständig erfüllt.
- [ ] Keine fachlichen Erweiterungen ohne Auftrag.

## Codequalität
- [ ] Struktur und Benennung sind verständlich.
- [ ] Guidelines werden eingehalten.
- [ ] Keine unnötigen Duplikate oder unnötige Komplexität.
- [ ] Fehler- und Randfälle sind berücksichtigt.

## Auswirkungen
- [ ] Keine unerwünschten Änderungen ausserhalb des Umfangs.
- [ ] Bestehende Schnittstellen bleiben kompatibel oder Änderung ist freigegeben.
- [ ] Konfiguration und Installation bleiben nachvollziehbar.

## Sicherheit und Abhängigkeiten
- [ ] Keine Secrets oder persönlichen Daten im Repository.
- [ ] Neue Bibliotheken sind notwendig, Version und Lizenz wurden geprüft.
- [ ] Logging enthält keine unnötigen sensiblen Inhalte.

## Tests
- [ ] automatisierte Tests erfolgreich.
- [ ] relevante manuelle Tests erfolgreich.
- [ ] Fehlerfälle geprüft.
- [ ] Resultat und bekannte Einschränkungen dokumentiert.
